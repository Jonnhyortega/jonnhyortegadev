# Admin CMS seguro — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend Express + panel admin para editar textos en/es, proyectos y paleta del portfolio, con seguridad de nivel producción.

**Architecture:** Express exportado como función de Vercel en `api/index.js`, Postgres en Neon vía Drizzle, sesión por cookie `__Host-session` tras Google OAuth. El sitio público lee `GET /api/content` (cacheado en CDN) y cae a `src/content/defaults.js` si falla. El panel es una entrada Vite separada (`admin.html`) servida solo en la ruta secreta `ADMIN_PATH` por `middleware.js`.

**Tech Stack:** Node 22, Express 5, Zod 3, Drizzle ORM + drizzle-kit, `@neondatabase/serverless`, `@electric-sql/pglite` (tests), `@node-rs/argon2`, `jose`, `helmet`, `cookie`, `@vercel/functions`, Vitest + Supertest, React 19 + Vite 7 + Tailwind 3 (existentes).

**Spec:** `docs/superpowers/specs/2026-10-16-admin-cms-design.md`

## Global Constraints

- El valor real de `ADMIN_PATH` **nunca** aparece en archivos commiteados, mensajes de commit, tests ni bundle. Tests usan `/test-panel-path`.
- Toda consulta SQL va por Drizzle (query builder o `sql` tagged template). Prohibido `sql.raw` con datos de entrada.
- Todo objeto Zod de entrada usa `.strict()`.
- `/api/admin/*` sin permiso → 404 con cuerpo `{"error":"not_found"}`, idéntico al 404 genérico.
- Fuera de `VERCEL_ENV=production`, `/api/admin/*` y `/api/auth/*` → 404.
- Cookie: `__Host-session`, `HttpOnly; Secure; SameSite=Strict; Path=/`, sin `Domain`.
- Sesión `full`: 8 h absoluta, 30 min inactividad. Sesión `recovery`: 15 min absoluta.
- argon2id: `memoryCost: 19456`, `timeCost: 2`, `parallelism: 1`.
- Códigos de recuperación: 10 códigos, 12 caracteres Crockford base32, formato `XXXX-XXXX-XXXX`.
- Rate limits: login 10/min/IP; recuperación 5/h/IP; escrituras admin 60/min/sesión; bloqueo global de recuperación a los 10 fallos 15 min, 15 fallos 1 h, 20 fallos 24 h.
- Body JSON máximo 64 KB; `Content-Type` distinto de `application/json` en escritura → 415.
- Hosts de imagen permitidos: `res.cloudinary.com`, `upload.wikimedia.org` (este último ya usado por el proyecto "API Chatbot").
- Commits: Conventional Commits en español, atómicos, con trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nada de push ni merge sin autorización.
- Nombres de identificadores en inglés; textos de UI y comentarios en español (como el código existente).

**Precisiones sobre el spec** (detalles de implementación que el spec no fijaba):
- `projects` suma `slug` (único, para seed estable) y `version` (control optimista por proyecto).
- La allowlist de imágenes incluye `upload.wikimedia.org` por un proyecto existente.
- Las variables del tema las calcula `themeToCssVars`, módulo compartido por servidor (respuesta de `/api/content`) y panel (vista previa).
- Reordenar proyectos usa botones ↑/↓ en vez de arrastrar, para no sumar una dependencia.

## Review Focus

1. **Cookie `Secure` en desarrollo local por HTTP:** `__Host-` exige `Secure`; en dev local el login no aplica (auth deshabilitado fuera de producción), pero el panel debe mostrar un mensaje claro "solo disponible en producción" en vez de un loop de login. → Test en Task 15.
2. **Contenido de la API incompleto o viejo** (claves nuevas en `defaults.js` que la BD no tiene): el merge debe rellenar con defaults sin romper `t()`. → Test en Task 14.
3. **Texto con caracteres Unicode/emoji o acentos** en traducciones: debe guardarse y devolverse intacto (no confundirse con caracteres de control). → Test en Task 12.
4. **Reordenar con lista de IDs incompleta o con duplicados**: rechazar con 400, nunca dejar posiciones inconsistentes. → Test en Task 12.
5. **Doble envío concurrente del mismo código de recuperación**: solo uno debe ganar. → Test en Task 10.

### Task 9: Login con Google OAuth + PKCE

**Files:**
- Create: `server/services/google.js`, `server/services/oauthFlows.js`, `server/routes/auth.js`, `tests/server/oauth.test.js`

**Interfaces:**
- Consumes: sesiones (Task 8), auditoría (Task 6), rate limit (Task 7).
- Produces:
  - `createGoogleClient(env) => { buildAuthUrl({ state, codeChallenge, nonce }) => string, exchangeCode({ code, codeVerifier }) => Promise<{ idToken }>, verifyIdToken(idToken, { nonce }) => Promise<{ sub, email, emailVerified }> }`. `verifyIdToken` usa `jose.jwtVerify` con `createRemoteJWKSet('https://www.googleapis.com/oauth2/v3/certs')`, `issuer: ['https://accounts.google.com','accounts.google.com']`, `audience: env.googleClientId`, y compara `payload.nonce` con `safeEqual`. URL de autorización: `https://accounts.google.com/o/oauth2/v2/auth` con `response_type=code`, `scope=openid email`, `code_challenge_method=S256`, `prompt=select_account`. Intercambio: `POST https://oauth2.googleapis.com/token`.
  - `createFlow(db, now) => Promise<{ state, codeVerifier, nonce, codeChallenge }>`; `takeFlow(db, { state, now }) => Promise<{ codeVerifier, nonce }|null>` (borra con `DELETE ... RETURNING`; null si no existe o expiró).
  - Rutas (todas tras `productionOnly` + rate limit 10/min/IP):
    - `GET /api/auth/google/start` → 302 a Google.
    - `GET /api/auth/google/callback?code&state` → éxito: crea sesión `full`, setea cookie y responde 302 a `/__panel-return`.
